# Система управления снабжением (Новая версия)

Улучшенная версия веб-приложения для отслеживания заявок на снабжение строительных объектов с использованием паттерна Наблюдатель (Observer).

## 🚀 Новые возможности

### Архитектурные улучшения
- **Модульная архитектура**: Разделение на слои (models, services, controllers, observers)
- **Паттерн Наблюдатель**: Автоматические уведомления об изменениях
- **Кеширование**: Оптимизация производительности
- **Валидация данных**: Улучшенная проверка входных данных
- **Обработка ошибок**: Структурированная обработка исключений
- **Логирование**: Подробное логирование всех операций

### Система уведомлений
- **Email уведомления**: Отправка email при изменениях
- **Slack интеграция**: Уведомления в Slack каналы
- **Логирование событий**: Запись всех изменений в лог-файлы

### Улучшенная бизнес-логика
- **Валидация данных**: Проверка корректности всех вводимых данных
- **История изменений**: Отслеживание всех изменений статусов заявок
- **Кеширование**: Быстрый доступ к часто используемым данным

## 🛠 Установка и запуск

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка уведомлений (опционально)

Создайте файл `.env` для настройки уведомлений:

```env
# Email настройки
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your_email@gmail.com
SMTP_PASSWORD=your_app_password
SMTP_FROM_EMAIL=your_email@gmail.com

# Slack настройки
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/YOUR/SLACK/WEBHOOK

# Включение уведомлений
ENABLE_NOTIFICATIONS=true
EMAIL_NOTIFICATIONS=true
SLACK_NOTIFICATIONS=true
```

### 3. Запуск приложения

```bash
python app_new.py
```

Приложение будет доступно по адресу: http://localhost:5000

## 🧪 Запуск тестов

python -m pytest tests/

## 🚀 Развертывание

### Production настройка
1. Установите переменную окружения `FLASK_ENV=production`
2. Настройте SMTP для email уведомлений
3. Настройте Slack webhook
4. Используйте WSGI сервер (gunicorn, uwsgi)

```bash
export FLASK_ENV=production
gunicorn -w 4 app_new:create_app
```

## 🏗 Архитектурные принципы

### Паттерн Наблюдатель (Observer)
- **Subject**: Сервисы (RequestService, SupplierService, SiteService)
- **Observers**: Email, Slack, Log наблюдатели
- **Events**: request_created, request_status_changed, supplier_created

### SOLID принципы
- **Single Responsibility**: Каждый класс отвечает за одну задачу
- **Open/Closed**: Легко расширять функциональность
- **Liskov Substitution**: Наследники полностью заменяют базовые классы
- **Interface Segregation**: Интерфейсы разделены по ответственности
- **Dependency Inversion**: Зависимости от абстракций

### Лучшие практики
- **Factory Pattern**: Для создания приложения
- **Blueprint Pattern**: Для организации маршрутов
- **Service Layer**: Для бизнес-логики
- **Repository Pattern**: Для работы с данными
